# Isolated event round and integration boundary

`event_matches.py` implements one borrowed-hand event battle; `event_matchmaking.py` implements authenticated E admission, owned-card selection, proposals, table admission, reservations and round cleanup. Eight round tests and22 coordinator tests pass, including complete two-human, three-human and one-human/synthetic-CPU rounds, original x86 consumers and failure isolation. `protocol_map/event_match_vectors.json` has117 original-code cases; `event_selection_lifecycle_vectors.json` adds25 selection/exit/counter/owned-restoration cases. No native game, graphics/input or server was launched by this pass. Root owns opt-in E routing and encrypted integration validation.

## Public API

- `EventParticipant(peer, character_id, name, nickname_id, cards)`: authenticated peer, unique positive character ID, byte name and exactly five validated cards.
- `EventMatchRound(participants, cpu_cards=None, seed=1, catalog=None, start_fields=None, turn_limit=2, departure_rule=1)`: two/three humans, or one human plus explicitly configured synthetic CPU. The CPU is local policy; global event mode8 is not identified as a computer mode.
- `begin()`: ordered deliveries EventGameInit01, recipient-private EventCard07, Start08, Turn09. Duplicate begin returns no output. Calling after cancel cannot restart the round.
- `handle(peer,payload)`: accepts only participant43/09 TurnData,0A PutData,0B BattleSelect and result0E Ready. Ordinary selection, admission, prizes, Continue, Quit and Break are rejected. Unknown primary returns None.
- `advance(max_battles=1)`, `pending_work`: same bounded CPU/battle scheduling pattern as MatchService.
- `phase`, `sequence`, `active`, `players`, `snapshot()`; `players` contains the underlying Player objects and must remain adapter-read-only under its lock.
- `outcome`: frozen character IDs, board scores, local result classes and aborted flag, for a separately configured event policy. It is not an award. `cancel()` aborts pending work without inventing a departure packet. `final_cards(peer)` always returns None.
- `event_session_init(session,rating=...,balance=...,points=...,count=...,rt=...,status=0)`: B2/13 EInit with required Stat presence.
- `event_session_quit(session,status=0)`: B2/17 EQuit D0 with exact header session. This builder does not establish when an unsolicited quit is appropriate.

Combat delegates to MatchService. Its small private subclass replaces the final end-turn branch so ordinary rating/money/result growth/prize/inventory commits cannot run. Battle-time transformations remain transient on the borrowed cards. The adapter must never pass this round through ordinary match settlement or replace owned inventory with its hands.

The original EventGameInit parser leaves bm and du unchanged. This module uses zero for both. Supply coherent zero bm/du through the published table/rule cache and PLAYACK first. The supported original reduced-six-card decode recomputes points; the module normalizes points using that same catalogue formula before combat. Each recipient receives only its five own cards, indexed by original server seat.

Pre-event selection temporarily moves cards out of the client's collection, but both confirm100FE4E3..54B and cancel100FEA11..76 export them back before EQuit. Five original cases verify the unchanged full compact-card/deck multiset after selection/restoration/EQuit. No return-card packet21 is required. The server correctly keeps owned cards unchanged throughout this borrowed-card battle, apart from explicit validated Decks edits.

## Coordinator adapter contract

Construct `EventMatchmaking(host, rooms, table_configs, hand_provider=None, clock=...)` under the adapter's match lock. None uses the authenticated client's selected five; an explicit `(config, immutable_account_view)` provider supplies a trusted replacement hand. Each `EventTableConfig(event_id, table_id, channel, player_count=2, cpu_cards=None, turn_limit=2, departure_rule=1, ...)` binds one separate playable table. The whole configuration set is validated on an isolated room map before live bindings change. Root must additionally exclude collisions with all authenticated account identities. Borrowed cards are validated in all eight fields before catalogue lookup; points are normalized using the original reduced-card calculation.

- `handle(peer, key, target_game_identity, payload, joined_channels=...)` returns ordered `EventDelivery(peer, source_game_identity, payload)` records, or None for another route. E98 is authenticated against room presence. Successful admission reserves the account against shop/trade/ordinary matches; duplicate E98 replays the cached99/EInit response.
- Init-route B2/07 performs selection; no proposal is emitted before it. `session(peer)` returns its header/session number. B2/17 Quit with matching No/session cancels preselection without closing the connection and returns EQuit; a duplicate repeats that reply. B2/22 persists owned deck-only changes under the reservation, refreshing its capability and any selected deck fields. Late same-session deck edits after clean finish/cancel use the idle-only economy API.
- `poll()` publishes pending table metadata and pairs ready entries. Metadata DD precedes D2 proposals. D3 Ans0 cancels already-consenting waits and schedules a two-second retry. All retries and table admission share the oldest entry's120-second deadline; neither traffic nor pairing extends it. Both values are configurable local policies.
- `pending()` returns `(event_id, epoch)` continuations; `advance(event_id, epoch, max_battles=1)` is bounded. Obsolete epochs are inert. The existing MatchWatchdog covers ACK120, decisions at original tl seconds plus60, processing30 and result900 seconds. No forced move or invented timeout packet is sent.
- `results()` exposes `(event_id, epoch, frozen_outcome, seat_keys)` immediately when a board completes, before emitting EventResult. Human keys use original server-seat order; CPU has None. Persist these facts and configured progress before result delivery, keyed by an adapter instance/generation plus event/epoch. `acknowledge_result` removes a durably recorded receipt; cancellation cannot discard an unacknowledged result.
- `completed()` reports all-Ready rounds. Call `finish(event_id, epoch)` only after durable settlement; it releases account reservations and publishes an empty table. Exact second native Ready after finish is idempotent for that peer/table/completed-counter/seat. Fresh admission or disconnect clears this tombstone.
- `disconnect(peer)`/`cancel(event_id, epoch)` invalidate active work, release the affected round and queue closures. Drain `take_closures()` and close peers outside the lock. No self-GetAway or invented active abort packet is sent. Other events remain independent.
- Active43/05 Quit validates the authenticated seat, replies Quit No/B0 and cancels the round. The quitter can complete its mapped exit panel; other humans are closed under the local unsupported-resume policy.43/27 Break validates character ID and header3, sends no invented acknowledgment and cancels/closes the round. Completed results remain durable facts; incomplete aborts grant no automatic win/progress.
- Invalid trusted hand-provider/configuration output aborts only its selected entries before publishing a proposal, releases their reservations and queues closures. Drain `take_errors()` for `(event_id, diagnostic)` records; these are local logs, never wire text.

`initial_updates()` and `routes()` support initial table publication/routing. `snapshot(event_id)` is diagnostic only. The coordinator requires fresh E admission for every round; it does not infer historical continuous tournament pairing or automatically award cards/currency.

## Constraints and remaining work

Global mode8 is explicitly excluded by the original matchmaking proposal gate. It selects alternate event-room panels and PTL/DE reload paths; no original CPU meaning is proven. Use Ans1 for the proposed implementation and leave Ans2 unsupported.

Ordinary room admission and EventGameInit are different barriers. A service E record with an E metadata prefix does not enter the derived playable-table vector: that vector requires A/B metadata and positive decoded number. Do not reuse the E service record as the only proposed table record.

Entry/exit session values, event eligibility and membership, proposal epoch, joined table, authenticated participant seat and event-round epoch need separate adapter state. On disconnect cancel pending work and invalidate that epoch before releasing its table; no client self-GetAway or invented reward should be sent. A subsequent connection must repeat room/session admission rather than resume stale protocol queues.

Event observers and native globalmode8 admission are covered by later EVENT_SPECTATOR_NOTES.md and EMULATION_COVERAGE.md. Active replacement/resume and historical departure penalties, original tournament pairing and full event progress/award rules remain unproved. The synthetic CPU uses the ordinary versus wire representation and is not advertised as authentic original event NPC behavior. Selection/quit session timing is now proven in the bounded original child/parent vectors; actual graphical scheduling remains untested.
