# Atomic match economy

`match_economy.py` supplies durable round escrow, completed money receipts, pending CBC cards and ordinary card-prize receipts. `EconomyService.commit_match_money` and `commit_match_transfers` validate all human participants before replacing any account state. These modules do not enable stakes, card prizes or a network route by themselves. Existing practice defaults remain unchanged until adapter and original-client packet checks pass.

## API and ordering

Construct `MatchEconomy(economy)` or `MatchEconomy.restore(economy, snapshot)`. Persist its snapshot in the same atomic document as economy, auction and ResultRewardService. A stable round ID includes table instance and round; IDs use the same bounded ASCII identifier domain as other ledgers. Completed IDs remain as replay tombstones. `status(round_id)` returns an independent summary, not mutable internal state.

1. `begin(round_id, reservations, stake, mode='versus', player_count=2, money_enabled=True)` takes human wire-seat to live MatchReservation. Versus requires all two or three human seats; computer requires exactly one human seat and two or three total players. It checks that every human owns at least five cards and every balance can cover the stake before atomically debiting once. It returns the same seat mapping with fresh capabilities. An identical retry with current capabilities does not debit again. New round IDs cannot overlap an unfinished round for any account. `money_enabled=False` requires stake0 and quotes zero credit even for computer wins, allowing card prizes independently of monetary rewards. The flag is durable and cannot change on replay; legacy snapshots lacking it retain True for compatibility.
2. `quote(round_id, reservations, scores, ratings)` computes the actual positive credits without mutation. Use this before constructing ResultData so D1 and durable result statistics agree with the exact credited amount. Scores/ratings are authoritative engine values in server-seat order. Ratings are restricted to the proved local arithmetic domain0..99999; board scores total1..25.
3. Commit original-five growth and coherent result statistics through `economy.commit_match_growth(rounds, stats_by_key, payouts_by_key)`; the last mapping translates the quote from seats to authenticated account keys. Then call `record_result(round_id, reservations, scores=..., ratings=..., cbc=...)` with the refreshed reservations. This credits money once, saves the result inputs/payouts and holds each human's CBC cards durably. It returns `(fresh_reservations, payouts)`. Persist before ResultData. Ordinary card choices may remain unresolved; no ordinary player cards have moved at this point.
4. Once the **entire** original PrizeLedger is complete, call `settle_cards(round_id, participants, settlement.transfers)`. Participants includes every server seat mapped to `(live_reservation_or_None, grown_original_five)` in **original selection-slot order**, not reconstructed board order. None means a trusted local computer hand. The boundary verifies each transfer's unique `(loser, original_slot)`, exact grown source tuple and exact deck255 received copy. It removes all human losses atomically and stores the earned receipts before returning `(fresh_human_reservations, combined_extras)`. Extras contain CBC first, then ordinary prizes, matching native append order.
5. `handoff(round_id, reservations, result_rewards)` stages one stable combined reward ID per human into the existing Continue/overflow service, including empty batches. It refuses an unrelated pending result before staging any account. Repeat handoff does not add another award. The caller then uses ResultRewardService for Erase/Decks and authenticated Continue, and copies its refreshed tokens as before. Persist before releasing the final held GetSelect/ResultData reply or successful Continue.

Do not stage an independent CBC ResultRewardService context before ordinary choices: MatchEconomy owns that durable CBC receipt until handoff. A winner may exceed1000 cards, so ordinary prizes are deliberately not inserted directly into the canonical inventory. Pending receipts plus the loser's removal are saved together. The real native overflow screen chooses discards before Continue commits the winner's final inventory.

Call `abort(round_id, current_reservations, auction)` before releasing a table's capabilities. It returns current/refreshed reservations. Unfinished escrow refunds exactly once. A completed result keeps its already-credited payout. If choices never completed, no ordinary cards are transferred and CBC still recovers. If transfer settlement completed, every unhanded award recovers through the trusted Returned Card queue with a stable source ID. Already handed cards belong to ResultRewardService's existing recovery, so run that cleanup too. Restore followed by `recover_all(auction)` performs the same recovery on idle accounts before listeners start; it does not invent native scene resumption. Save every changed ledger atomically.

## Explicit local policies

Human-versus money is a zero-sum pot. All participants contribute the same stake0..2000. Highest-score seats divide the pot equally using integer division. Any integer remainder or balance-cap overflow is refunded to contributors in ascending server-seat order, each refund bounded by their contribution and remaining balance capacity. This preserves the total money exactly and never silently drops an overflow. Fully tied results refund all stakes. This policy is intentionally chosen for the replacement server; the original online payout policy is unavailable.

Computer matches with money enabled use the original offline client formula exposed separately as `offline_payout(scores, ratings, stake, seat=0)`. If all scores tie, payout is the stake. Otherwise L is the number of strictly lower scores, r is the truncated mean other-player rating, f=`100+trunc((400-r)/2)`, and m is3 for a perfect score or1 otherwise. Payout is `trunc(f*(stake+100)*m*L/100)`. The pure function preserves signed arithmetic; hosted credit clamps a nonpositive result to zero and caps the actual credit at remaining99,999,999 balance capacity. This is recovered **offline** arithmetic selected as a hosted policy, not proof of historical online behavior. It can pay a bonus at stake0. The adapter must pass its explicit monetary opt-in to `money_enabled`; False bypasses this bonus and guarantees D1=0 agrees with the durable credit.

An interrupted, uncompleted round refunds its entire stake. A completed result retains its payout even if card choice or the exit dialog is interrupted. Ordinary prize choices that never completely resolved cause no player-card loss. These are explicit durable local interruption policies; the client's cleanup refund predicate alone cannot prove historical server behavior. CBC already earned at the completed result remains recoverable.

`next_stake(stake, double)` ports the original bounded doubling rule. Merely calling it or opening Continue changes no balance. The adapter must begin a new round only after **every required Continue acceptance**, and reject unaffordable rematches before a positive response. A no vote charges nothing.
