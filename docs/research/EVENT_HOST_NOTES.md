## Integration

Construct `EventHost(economy, configs, clock=...)`; the default configuration list is empty. Restore with `EventHost.restore(economy, configs, saved_events, clock=...)`. Save `host.snapshot()` in the same atomic document as the economy before acknowledging any changed membership/progress. No I/O is hidden inside the service.

Each frozen `EventConfig` takes `id`, `listing`, full `data` bytes generated by `event_data`, signed `start/end`, and distinct game-domain `room_id/init_id/card_id`. Optional init/card channels must be terminated within the original 16-byte raw field. `entry_answer` is explicitly 1 or 2, mapping to original mode4 or mode8. The current E reply uses `Card=0`, meaning the client's own-card shortage gate remains active. It does not promise a loan deck. The time window is a chosen local half-open interval `[start,end)`, not an inferred historical schedule.

`match_enabled=False` and `card_service_enabled=False` are separate default capability gates. Neither service should be advertised until its downstream protocol is implemented. `config.service_records()` supplies only enabled raw PTL records: E for event initialization, F for the separate card service. These are 0x68 bytes each, with service qword+0, zero DWORD+0C, channel+18, and metadata+28 consisting of E/F plus 48 A bytes. Original100761F0 and1009A080 select these exact fixture records. Their opaque zeros are local fixture choices. The adapter must append records to the correct event-room PTL, update the raw count, and publish compatible event room/directory records; this helper is not a complete room advertisement.

`event_for_service(game_id)` returns `(event_id, route)`, where route is `room`, `init` or `card`. After target/source validation, call:

```python
replies = host.handle(account_key, payload, event_id=event_id, route=route)
```

It handles 90/CardReq on F, 98/EInitReq on E, and D1/04 EventTimeReq on the room. It returns `None` for unrelated families. Send replies from that service's published identity. NN must equal the authenticated account NN; CN must exactly match the account name; HID, Dm and Vol must fit their original widths. For EInit GID, the local profile implementation currently recognizes two owned aliases, `account.player_id` and `account.nn`. These aliases are an explicit local binding, not proof that original NN and GID were interchangeable.

For a successful room DE, first perform the adapter's normal presence/identity checks and generate its DE response, then call `admit_room(key,event_id)`, persist, and emit the returned D0. Original10096970 requests DataList, D1 time and DE before waiting for D0 at state6. There is no preceding client D0 request. This method permits registration before the configured start, rejects new admission at/after end while allowing existing members to reenter for durable claims, caps durable members at256, and rejects a negative eligibility entry. Repeated admission preserves all progress and does not add duplicate members.

After a positive E response and at least five owned cards, `admission(key)` returns an immutable `EventAdmission` with `kind='init'` and mode4/8. The adapter must still atomically reserve/register the actual event match before sending its success messages; `complete_admission(key)` consumes this context. `EconomyService.is_busy(key)` now covers reservations **and ordinary shop sessions**, so event entry cannot accept an account currently using either. Under-five-card E requests retain the original positive99/Card0 shortage-dialog behavior but create no match context.

A positive F response instead creates `kind='card', mode=None`; it is not a match context and has no minimum-five-card requirement. Its capability defaults off and may be enabled with the separately integrated EventCardService. Do not register this context in MatchService.

`disconnect(key)` clears room presence/admission but preserves durable membership/progress. Restore likewise never fabricates an active room or resumes a native scene. E match initialization requires authenticated DE after reconnect. F collection instead accepts existing durable members after reconnect, including after the event end.

## Files and durable progress

`file('b/g/TM0EventList')` publishes all configured listings. `file(path,event_id)` selects DataList or MemberList explicitly. The old `file(path)` shape is supported for zero or one configured event; with multiple configured events, ambiguous DataList/MemberList reads fail rather than choosing a different room's data. Original profile_owner_vectors.py/json now proves the packed transport owner in48 cases: raw41POL | ((directory&127)<<41) | ((volume&65535)<<48). The adapter routes the event using game_id(owner & 0x1FFFFFFFFFF), with upper bits kept as directory/volume metadata. Multi-event reads must use that explicit owner route; the single-event fallback is only a compatibility helper.

Member identity is account NN, independently verified by original1014BC36..1014BC55 copying102B2918/1C into102B5308/0C. Original member lookup compares102B5308; it does not compare GID102B52A0. GID is separately read by98 at1008BD8D and CR/PG paths such as1008AC86. Member names must fit15 bytes plus NUL. Steps preserve the full nonnegative signed-DWORD range; nickname metadata elsewhere uses only the low byte. Mission bits must be among the at-most-three configured low-byte missions.

Trusted server policy/engine code may call:

```python
host.update_progress(key, event_id, update_id,
                     steps_delta=3, completed_missions=0x04)
```

Each `(event,key,update_id)` is durable. An exact replay is a no-op; different facts under the same ID fail. Steps add without wrapping; newly completed bits OR into the member mask. Disabled mission bits, negative counts, signed overflow, absent members and excluded members fail atomically. The wire handler never accepts progress claims. This API has no hidden money, inventory, ranking or Prize Center side effect. Original mission descriptions do not establish authoritative thresholds, so no automatic mission counting or award calculation is installed.

`set_eligibility` is a trusted administration API. A negative value preserves history while excluding/rejecting the member. For an existing member, EInit returns the original -32872 branch; room admission returns -32870. This association with local exclusion is a chosen server policy. The mapped99 -32968 branch is used for a finished event; before start, busy account, missing room presence or disabled service uses -32870. F collection deliberately permits existing eligible members after end to recover durable grants; disabled/busy/missing-member or excluded requests use -32870. This post-end access is a local recovery policy.

Snapshots carry a fingerprint of each event's listing/data/schedule/identities. Changed configurations fail restore instead of reinterpreting old progress. Capability gates are excluded from this fingerprint, so completing an implementation can safely enable a configured route. The restore validator checks owner NN, member capacity, mission domains and that member totals exactly agree with the durable update history. Unknown/duplicate IDs or edited totals fail closed. Added empty configurations are permitted; silently deleting a saved event is not.

`time_update(event_id)` creates D1/03 with raw Now. `time_notice` supports D1/01 Start,02 End,08 Close with optional ECM. These are explicit adapter operations, not an invented historical scheduler. D1/05 reports Start/End/Now and the original receiver derives End-Now. The tests execute both distinct receiver contracts.

## Separate F card-service path

The connected original100FF270/100FFE50 trace and28 original cases now establish F as event prize collection. It uses B2/EcmInit, reveals up to nine cards, sends Get before reveal when capacity fits or after overflow edits, animates PM money without an acknowledgement, and exits through B2/Quit. It never starts43/EventGameInit. The implementation, exact addresses, durable grant policy and integration contract are documented in EVENT_CARDS_NOTES.md.
